## 代码层修复

`tools/build-data.mjs` 已增加公开发布门禁：

1. 仅 `已核验` 隐患可进入运行库；
2. 其关联条款必须为 `已核验`；
3. 关联法规必须为 `现行有效`；
4. `待核验` / `已失效` 内容可以保存在 source staging，但不能进入 `data/` 公开运行数据；
5. manifest 增加 staged 统计，避免以后再次出现候选数据误上线。

## 当前接手顺序

1. 使用已完成的目录及身份合并接口，按私有 `reports/requirements-next.json` 和 `register-queue/` 继续分组处理。
2. 按法规版本共享官方证据，通过 `review.py` 保存实际审阅结论；不得直接维护网站 JSON 或用状态单元格制造通过。
3. 对标准替代关系重点检查 2026 年新实施标准，尤其 GB 14444—2025、GB 55037—2022 以及危废现行标准。
4. 旧纠偏/hold 脚本已从常态 CI 移除，保留历史文件；不能让它们覆盖后续母库核验结果。
5. 用严格发布器生成新目录，对比隐患增减及门禁原因。只要求公开待核验为 0，母库可以长期有待核数据。
6. 补齐证据、审阅发布差异及生产切换方案后，再另行处理 main 和正式部署；本轮 24 条严格预览不能自动替代现有网站。
