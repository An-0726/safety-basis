## 4. 可运行的检查工作台

工作台由本机 Python API、私有 SQLite 和浏览器界面组成，Node 桥接复用原法规检索系统。已实现：

- 企业项目创建与修改；现场位置、设备、原话、专业描述、整改措施和责任信息录入。
- 多张现场照片上传、预览、说明、排序及移除；图像重新编码并去除 EXIF。
- 正式条款检索、场景选择、引用快照和适用条件核实；区分现场隐患与资料核查。
- 逐项事实记录、提交、专业审核、退回和重开，保留审核与操作轨迹。
- Word/PDF 报告、原文及条件附件、照片清单、报告历史与不可变快照。
- 私有备份和向空目录恢复；可替换 Word 模板及版式配置。

本轮独立审查发现并修复了三类重要边界：修改企业或检查日期等项目条件会重置事实和审核；旧 revision 的事实与审核请求被拒绝；法源尚未施行、快照不能覆盖检查日期、依据被移除或内容改变时，阻止确认及新正式报告导出。仅有辅助依据、必要事实未确认或核实说明缺失，也不能通过审核。已导出的历史报告保持原样。[业务实现与限制](../workbench/README.md)

### 本地启动与示例导出

需要 Python 3.11+、Node.js 22+。在仓库根目录执行：

```sh
python -m pip install -r tools/pipeline/requirements.txt -r workbench/requirements.txt
python -m workbench prepare
python -m workbench
```

打开 `http://127.0.0.1:8765/`。默认业务数据保存在用户目录下的 `.safety-basis-workbench`。可通过 `--data-dir` 指定仓库外私有目录；历史日期核查使用 `prepare --as-of YYYY-MM-DD` 准备相应知识包。

合成样例及可复现的 Word/PDF 导出：

```sh
python -m workbench demo --export --data-dir /private/workbench-demo
```

命令打印报告目录，包含 `inspection.docx`、`inspection.pdf` 和 `snapshot.json`。网页创建样例时默认保留待核事实；上述 CLI 的 `--export` 仅为新建的合成示例模拟核实和审核。样例照片与记录均不对应真实企业。模板替换方法见[模板说明](../workbench/templates/README.md)。
