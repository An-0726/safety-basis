# 有证据的核验与网站数据构建

`review.py` 登记实际审阅结论；`manage.py site` 从母库筛选通过全部依赖核验的记录，生成完整独立网站包。生产网站仍使用旧基线；候选包通过选择文件和 CI 构建托管 artifact，正式发布须在 `main` 手动触发。

## 核验对象

| 对象 | 核验内容 |
| --- | --- |
| `law` | 规范名称、制定机关、地区、文种及法规身份唯一性 |
| `law_version` | 本版本名称、文号、效力、有效期间、官方来源 |
| `clause` | 条款定位、对应版本、原文 |
| `hazard` | 隐患描述、整改、适用条件、分类与公开字段 |
| `link` | 该条款能否支持该隐患，依据角色及地区/对象边界 |

旧数据的 `legacy_inherited` 记录保留原状态来源，不等于重新核验通过。单独把状态改成“已核验”、有官方 URL、原文存在于某份文件，都不足以发布隐患。

## 保存官方证据

先从官方来源取得并查看原件，再登记文件、稳定官方 URL 和实际获取时间：

```text
python tools/pipeline/review.py evidence --snapshot source/proposals/official.docx --url https://example.gov.cn/official-detail --retrieved-at 2026-09-09T09:00:00+08:00
```

以上 URL 和时间是语法示例，应替换为实际材料；登记不会联网取证，也不会自动判定其效力。原件按 SHA-256 存入私有归档；登记返回 `evidenceId`。同一原件可以支撑多个条款。法规效力元数据与正文可以分别作为证据登记；不要保存临时签名下载 URL。

当前支持可提取文本的 HTML/文本、DOCX 和 PDF。扫描件没有可靠文本时拒绝通过，需后续经过核对的 OCR 适配。当前官方 URL 白名单为政府 `gov.cn` 域；不在此范围的正式出版来源需以后扩展来源规则，不能临时伪装域名放行。

## 计划、审阅、提交

```text
python tools/pipeline/review.py plan --targets law:LF_L001 law_version:L001 clause:C001 hazard:H025 link:K_EXAMPLE --output source/proposals/review-001-draft.json
python tools/pipeline/review.py propose --review source/proposals/review-001-draft.json --reviewer reviewer-name --model actual-model --output source/proposals/review-001.json
python tools/pipeline/review.py apply --proposal source/proposals/review-001.json --actor operator-name
```

目标 ID 以当前母库为准；`K_EXAMPLE` 为占位示例。`--db` 是全局参数，必须放在子命令前。每批 1–100 个目标。

`plan` 固定母库状态指纹，带出每个目标的 revision、依赖哈希、审阅材料和未齐备字段。审阅者只填写 `decision`：`result`（passed/failed/pending/not_applicable）、`evidenceId`、`locator`、`reason`、`reviewDueAt`、`publicFieldsReviewed`。待整理内容通过 Excel 编辑提案补齐后，应重新生成核验计划。

通过记录必须有官方原件、精确定位、审阅人和理由；隐患还须确认公开字段已审阅。条款通过时，程序要求原文在原件提取文本中完整出现，只忽略空白，保留标点、否定词、数字和单位。**文本匹配并不自动证明条号正确或适用性成立；条号、版本和适用边界仍须实际审阅。** 不确定填写 pending，不能把任务完成当成 passed。

核验、明细、证据及回执追加保存；新 failed/pending 会覆盖旧 passed 的发布效力，但不删除历史。记录被关闭后不会因一次核验重新启用。整个提案单事务提交，过期快照拒绝、重复提交返回原回执；同批和跨批重复法规身份均不能同时确认。操作者和模型字段是审计信息，不是身份认证或数字签名。

## 发布门禁

发布日按中国时区 UTC+8 计算。每条公开隐患必须满足：

1. 隐患内容完整，存在对应当前 revision、当前内容及依赖的最新通过记录。
2. 至少一个启用依据关联，所有启用关联及其适用性均通过。
3. 关联条款原文和定位通过，无未解决身份冲突。
4. 法规身份已确认，本版本已核验且发布日在其有效期间内；待定、废止、尚未生效版本均阻断。
5. 核验证据原件存在且 SHA 匹配，获取时间与核验时间合理，尚未到复核日期。

内容、依据集合或父法规变化会使旧依赖哈希失配，统一阻断受影响条目。停用关联也改变隐患核验材料，不能靠去掉待核关联沿用旧通过记录。纯核验状态更新不制造内容变更。

独立法规索引可以包含没有公开隐患引用、但本身已经通过核验的现行版本及已发布、尚未实施版本。按用户 2026-09-09 的明确要求，尚未实施不是待核验：核对名称、版本、官方公告和实施日期后，未来版本可以发布目录及已获准公开的全文，界面标记“已发布 · 尚未实施”并显示实施日期及已收现行版入口。未核验、已废止或过期证据仍阻断。到达实施日后须复核版本状态，不能把旧“即将生效”标记静默改成现行。

自`safety-release-v2`起，公开名称自动包含母库版本的文号/标准号，避免不同年份版本在搜索中无法区分；旧v1快照继续按其原格式重建。全文公开审阅清单可选填`validityNote`，仅允许已审阅的公开文本，用于准确说明修改单、部分条文废止等版本边界；不自动公开内部核验理由。

隐患链仍按发布日检查依据是否已经实施，未来版本不会提前成为当前隐患的定性依据。条款仅导出被公开隐患引用的条款；全文库可独立收录尚未实施版本。母库长期保留待整理和待核验数据；公开 pending=0 不代表母库全部完成。

## 一条命令生成网站数据

```text
python tools/pipeline/manage.py site --as-of 2026-09-09 --output source/releases/NEW_RELEASE
python tools/pipeline/manage.py verify-site --output source/releases/NEW_RELEASE
```

可加 `--db <母库副本>`、`--node <Node可执行文件>`、`--baseline <旧search-index.json>`。默认基线为仓库现有搜索索引。输出目录必须尚不存在，拒绝覆盖当前 `data/` 或已有发布包。

输出包括 `release.json`、`data/manifest.json`、`search-index.json`、`law-index.json`、`taxonomy.json`、隐患与条款分片、`checksums.json`。Node 构建器仍负责网站 V2 格式；不需要人工修改任何网站 JSON。

私有阻断与新增/撤下清单单独写在输出目录旁的 `<目录名>.review.json`，不进入公开包。发布快照按字段白名单投影，不包含原始行、本地路径、企业现场信息或内部核验理由；公开摘要中的审核人、模型和定位应使用适合公开的文本。清空或撤下条目会产生 `requiresPublicationReview=true`，命令始终返回 `deployed=false`。

白名单只控制字段，不能自动识别任意文本里的敏感事实，所以隐患公开内容仍须审阅。快照哈希用于完整性与版本绑定，不是法规真实性证明或防恶意篡改签名。

从已审阅快照可脱离私有母库重建：

```text
python tools/pipeline/manage.py build --release source/releases/pilot-20260909/release.json --output source/exchange/pilot-rebuild-001
```

此过程再次检查实体、当前核验摘要和依赖哈希，并使用快照固定日期确定性生成数据。它验证快照内部一致性，不能替代从母库发布时对私有证据原件的检查。CI 在临时目录执行同样重建，不接触本地母库、不访问实时法规网站。

## Luna 分工与下一步

按法规版本分配小任务，共享一份官方证据，Luna 负责字段提取、逐字对照和无争议初审；主代理处理适用边界、版本替代、冲突以及最终提案。子代理只输出决定，不直接写母库。

同一轮并行结果须汇总进同一基础快照的一个提案后统一提交。当前使用整个母库状态指纹；另一批提交后，旧草稿会失效，下一批需重新 plan 并核对材料，不能修改指纹强行回收。本轮曾尝试 Luna/high，但启动返回 503 `auth_quota_exhausted`，没有得到子代理产出，实际闭环由主代理完成。

下一步先补新增法规、版本、条款和关联的受控提案接口，以及法规身份/条款冲突解决。之后再按法规分组小批扩大核验，逐步补齐既有公开数据证据。生产切换另需审阅完整增减差异、处理法规替代关系的公开展示、旧 ID 去向和 Service Worker 缓存；此轮尚未切换或上线。
