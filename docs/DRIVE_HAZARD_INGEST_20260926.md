# 2026 云盘现场隐患补库审计（2026-09-26）

## 一、范围与原则

本批按用户授权，对 2026 年云盘中的最新安全评价报告、现场检查记录、隐患整改记录及明确标注 2026 日期的现场资料进行筛查。企业名称、联系人、身份证、签字、照片等私有信息不进入公开仓库；只保留去企业化后的通用隐患事实。

处理顺序固定为：

1. 与既有 active / proposed canonical 隐患去重；
2. 已有正式隐患优先复用，不新造 Stable ID；
3. 只有“法规/标准身份 → 当前版本 → 完整条款原文 → authoritative evidence → 隐患适用性 → review hash”闭环后才进入 active；
4. 证据或现场条件不足的事项继续保留 proposed / 条件化边界；
5. 不以“未关联条款数量”反推“缺多少隐患”，不做无目的条款铺库。

## 二、资料筛查结论

- 2026-09-25 最新安全现状评价报告的 7 个评价单元共 110 项检查均为“符合”，报告明确“本次未列需限期整改的不符合项”，因此本批未把其预防性建议伪造成现场隐患。
- 2026-09-21 既有商贸检查全量补库的 16 份 Word / 134 条来源事项已复核，历史 1 月检查问题实际已包含在 SC001–SC134 映射中，不重复入库。
- 2026-09-20 粮库输送机急停、烘干燃料 SDS/警示、动力柜门保护连接、化验室酒精及仓储“五距”等问题已在 2026-09-21 工程审计批次处理；其中事实条件不足的燃料 SDS、酒精储存等继续保持条件化边界。
- 云盘中存在若干“2026 年上传但实际属于往年项目”的旧检查/整改材料，已结合项目台账排除，避免把历史问题误算为 2026 新增。
- 7–9 月部分 legacy `.xls` 标准化打分表仍需单独做来源覆盖差异审计；在未确认其与既有 1,929 条目标集的关系前，本批不据此重复造隐患。

## 三、本批正式化的高频现场问题

### 1. 安全警示标志褪色、污损或损毁

- 复用既有 `H_COM_SIGN_FADED`，由 proposed 转为 active；
- 新增 `GB 2894-2025` 第7.4.1条完整原文；
- 直接关联：`K_GB2894_7_4_1_H_COM_SIGN_FADED`；
- 现行标准要求至少每半年检查安全标志牌，发现褪色、变形、缺失、损毁、遮挡等情况应立即更换或采取措施。

### 2. 变配电室缺少防止蛇、鼠等小动物进入的设施

- 新增 `H_ELECTRICAL_ROOM_SMALL_ANIMAL_PROTECTION`；
- 新增法规身份/版本：`GB 50053-2013《20kV及以下变电所设计规范》`；
- 直接依据：第6.2.4条；
- 措施不写死为“必须挡鼠板”，允许根据门、窗、通风口、电缆沟实际条件采用挡鼠板、网罩或其他等效措施。

### 3. 安全出口或疏散指示标志灯具损坏、不能正常指示

- 新增 `H_EXIT_SIGN_LAMP_FAULT`；
- 与“未设置/位置不符合”分开建模；
- 当前先以《中华人民共和国消防法》第十六条第一款第（二）项作为直接法定义务：消防安全标志应定期检验、维修并确保完好有效；
- 后续如取得并完成具体消防应急照明系统维护条款的独立核验，可再补更细技术依据，不影响本项当前法定义务成立。

### 4. 消防控制室消防专用电话总机或专用通信功能失效

- 新增 `H_FIRE_CONTROL_PHONE_FAULT`；
- 新增 `GB 55036-2022` 第12.0.10条完整原文；
- 直接要求消防控制室设置消防专用电话总机、可直接报火警的外线电话，且消防专用电话网络为独立消防通信系统。

## 五、未在本批强行处理的事项

下列事项继续遵循“先事实、后依据”的策略：

- 燃料身份未知时，不自动认定其属于危险化学品并强加 SDS/标签义务；
- 酒精浓度、数量、包装及使用方式不清时，不写死“必须防爆柜”；
- 灭火器数量不足必须结合配置单元、火灾种类、危险等级、保护距离等计算；
- legacy `.xls` 打分表在与既有目标集完成来源差异核对前，不直接重复导入。

本批仅解决高频、重复出现且能够形成完整直接依据闭环的问题。
