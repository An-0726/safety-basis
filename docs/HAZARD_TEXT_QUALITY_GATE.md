# 隐患公开文本质量门禁

法规、版本、条款、关联和证据链全部通过，仍不能证明隐患公开字段可读且语义正确。`tools/pipeline/hazard_quality.py` 因此在核验准备和发布阶段执行确定性检查；命中后，隐患不能取得新的通过记录，既有通过记录也不能继续进入发布包。

当前硬阻断只覆盖高置信度结构损坏：前导标点或孤立列表序号、重复标点、已知的机器转译错位词组、只有法规引用而没有隐患描述、超长法规整段复制、明显正向义务或符合项被当作隐患，以及多个处于“已核验”状态的相同标题。规则不自动改写隐患，也不判断法规适用性。

发现问题时，应使用 `review.py plan → propose → apply` 追加一条 `failed` 或 `pending` 核验记录，使记录退回“待核验”。原始来源、历史核验、关联和母库记录全部保留。清洗后的标题、描述或措施必须通过受控修改递增 revision，再重新审阅公开字段和依据链。

2026-09-11 的发布审计发现，原“并发重验批次”只用关联条款生成统一理由，不能证明 366 条隐患的公开字段被实际审阅；连同其他明确异常，共 392 条记录通过追加失败结论退回待核验。审计文件位于私有工作区：

```text
source/exchange/continuation-20260911/hazard-publication-audit/
```

最终公开候选为 `source/releases/reviewed-20260911-r13/`。它只保留 33 条通过完整门禁且未命中文本质量规则的隐患；被撤下的数据没有删除，待后续清洗和逐批复核后可重新发布。
