## 2. 已实施的高价值修复：防雷定期检测版本衔接

唯一因此恢复当前发布资格的隐患是 **`H_89016FC0F3E849C2B8B8755C35` — 投入使用后的雷电防护装置未按适用周期检测**。原 `LV_CMA_LIGHTNING_MANAGEMENT_2025` 已有 `endDate=2026-11-01`，修复前并没有可接替的合并版本；Gate 在 11 月 8 日正确移出了这条规则及其两条依据。问题是法源承接缺口，未改动过期判定。

### 官方依据与逐字对照

已实际读取中国气象局[现行合并正文](https://www.cma.gov.cn/gzk/202504/t20250429_7036385.html)、[现行合并 PDF](https://www.cma.gov.cn/gzk/202504/W020260918628488027941.pdf)以及[2026-09-18 官方公布报道](https://www.cma.gov.cn/2011xwzx/2011xqxxw/2011xqxyw/202609/t20260918_8049644.html)。PDF 第 1、4、5 页已渲染目核。现行合并文本说明“根据2026年9月11日《中国气象局关于修改〈防雷减灾管理办法〉的决定》修订”；官方报道将该修改和另两部新规一并说明为“自今年11月1日起施行”。合并正文末条保留的是原办法 2025 年施行日期，因此修改生效日期使用该官方公布报道单独举证。

|条款|2025 与 2026 合并文本核对结果|本规则证据角色|
|---|---|---|
|第十三条，合并 PDF 第 4 页|逐字一致：投入使用后的雷电防护装置应当根据国家有关建筑物防雷标准实行定期检测制度。雷电防护装置应当每年检测一次，对爆炸和火灾危险环境场所的雷电防护装置应当每半年检测一次。|direct：定期检测及周期|
|第十七条，合并 PDF 第 5 页|逐字一致：已安装雷电防护装置的单位或者个人应当主动委托有相应资质的雷电防护装置检测机构进行定期检测，并接受当地气象主管机构和当地人民政府安全生产管理部门的管理和监督检查。|supporting：委托有相应资质机构|

第 44 号是原公布令号；本轮没有猜测修改决定的令号。第 21 条修改涉及雷电灾害风险评估，并不改变此次已核对的第 13、17 条检测义务。

## 3. 266 条候选全部形成可领取的补证记录

新增只读工具 [knowledge_closeout.py](../tools/checks/knowledge_closeout.py)，复用正式 `release_gate_core`，不另造法规准入逻辑。它从知识源按稳定 ID 枚举全部 proposed，记录原适用条件、完整 H/K/C/LV 审核情况、Gate 理由、官方位置或原表定位线索、逐项最小补证动作、必须确认的现场事实和排序理由。

|互斥主要缺口|条数|当前处置|
|---|---:|---|
|尚无精确条款关联|136|保持候选；按题名和原记录线索找发布机关/国家标准官方原文，先定位具体义务|
|原依据或关联已拒绝、存在错配|111|保持候选；复核原拒绝原因，对照完整条文的对象、条件和义务，不能用同名或概括义务代替|
|适用性或条款审核待补|17|保持候选；确认适用对象、责任主体、交叉引用及现场条件后实质复核|
|官方原文证据未完整记录/引用未解析|2|保持候选；补足真实可访问证据、身份、版本及精确条文定位|
|合计|266|266 条全部保持 proposed；公共发布 0 条|

主分类只用于不重复计数，每行的 `gapCodes` 仍列全部缺口。原记录中的标准名称、条号和历史 note 均明确标成**未经确认的定位线索**；不会被当成当前法源证明。

交付两份可直接使用的队列：

- [全量 266 条 JSONL](CANDIDATE_INVENTORY_20261108.jsonl)：每个 proposed 恰好一行，带原始文件、内容哈希、条件和具体动作，适合继续导入审核工具或脚本。
- [优先 40 条](CANDIDATE_PRIORITY_20261108.md)：按爆炸/中毒窒息/高温介质/燃气等场景后果相关性、已有可核定位、描述具体程度排序；同分按稳定 ID 排序。分数是**补证工作优先级**，不能作为尚未观察企业的风险等级或重大隐患结论。

本轮没有用生成的清单冒充 266 次官方原文实审。它完成的是全量现况盘点、可追溯处置与领取队列；高价值官方实修是上一节可完整核验的防雷版本承接。

[逐 ID 表](KNOWLEDGE_CLOSEOUT_20261108.md)及同日 JSON 的 `activeExcluded` 给出标题、关联 ID、具体 Gate 拒绝原因和最小动作。按主要原因可概括为 6 条依据/关联已拒绝、4 条内容或关联待审、1 条已过期版本未形成合格当前支撑。这里保留原生命周期和稳定 ID，仍继续排除当前发布。

## 5. succession 与版本影响复核
