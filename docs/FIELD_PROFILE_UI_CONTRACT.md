# 正式搜索中的核查用途与场景适用性

UI层仅消费统一发布包已审核的 `fieldProfiles`，不创建或修改法规、隐患、关联、审核记录，不把旧试验页作为正式入口。不新增一级分类或页面。底层治理口径见 [FIELD_PROFILE_CONTRACT](FIELD_PROFILE_CONTRACT.md)。

## 最小交互

- 首页默认保留全部正式结果，无配置的条目照常查询；更多筛选中的“核查用途”可选。筛选只覆盖已审核的场景，不能把未归类解释为不适用。结果数量仍按隐患实体，不按场景数计。
- 已有详情内提供“条件 / 场景适用性”。选择场景不是现场事实输入或认定；不选择也能查原条目。已选场景显示原样适用条件、避免误判边界、取证要求、整改方向及精确选定K的范围。下方原条目的全部依据仍保留，不能自动并入所选场景。
- 有模板的场景只展示未填参考，变量保留为中文占位标签。不填入位置、企业、设备或测量值，不产生完整现场结论。`routing_only` 与其他 `findingTemplate=null` 场景不提供隐患描述模板。
- `exclude` 只表示不进入默认现场检查用途，不删除原条目，不表示法规不适用，更不表示已发现隐患。资料核查和法规义务继续可检索、可查阅。
- 场景选择仅存当前页面内存，刷新即清空；不写入URL、localStorage、sessionStorage、Cookie或外部服务。“全部重置”同时清除选择。无企业资料字段或上传入口。
- 复制仍从当前正式详情产生；存在场景配置时统一标“核查参考，非已核实现场隐患”。已选场景附原条件、边界、模板参考和逐K范围；不把选择变成合规/违规确认。场景选择不进入分享链接。

## 加载与失效关闭

1. 只允许 `VerifiedFiles.read(manifest.files.fieldProfiles)`，不使用旧版未校验fetch回退；文件必须在当前发布清单中并通过SHA-256。
2. `schemaVersion`、真实日历 `asOf`、发布清单日期、公开计数和唯一ID一致。严格限制公开及嵌套字段，拒绝事实值或审核私有字段混入、非法路由、非法模板变量。
3. 每个场景与当前正式H及其选定K/C/LV精确join；原条件按统一构建器的null→空字符串规则比对。原K角色、条件和地域独立保存，不从条文标题或其他关联补推。
4. 前端检查选定公开版本/条款的有效状态、实施日期、可用终止日期、显式核验日期、正文与安全官方链接。原文来源若是非URL定位说明，回退到同一已发布法规版本的HTTP(S)来源；不把说明当作链接，也不改知识源。
5. 一个配置或依赖未通过，整份配置原子关闭；提示“核查场景暂不可用”，原条目搜索保持可用。零配置合法。缺审、审核过期、证据缺失及完整依赖链在后端当前日期Gate中关闭，浏览器不重新签审或放宽它。
6. 发布数据是明确 `asOf` 快照，非实时现行性保证。前端不会从无日期字段推断永久有效，原有过期/未来快照提醒保留；知识源新失效/变更需通过Gate重新构建发布。本次没有新增自动更新或实时监控。
