# 维护源数据

`content/` 是网站数据的唯一维护源。`data/` 是由构建脚本生成的运行文件，不手工修改。

## 文件职责

- `hazards.json`：一条事故隐患一条记录，只放隐患本身的信息。
- `laws.json`：一部法律、法规、规章或标准一条记录，保存名称、层级、地区、效力状态和来源链接。
- `clauses.json`：法规原文按实际引用的条款拆分，条款通过 `lawId` 指向法规主表。
- `links.json`：隐患与条款多对多关联；`role` 说明“直接依据 / 优先直接标准 / 上位法兜底 / 地方补充”等角色。
- `settings.json`：数据版本、构建日期和分片大小。

## 维护原则

1. 同一法规原文不得复制到多条隐患中，应复用 `clauseId`。
2. 同一隐患的不同适用条件应优先通过 `note`、场所、关键词和关联条款表达；确实是不同现场缺陷时再拆成不同隐患。
3. 已核验条款必须有原文和可追溯来源；拿不准时保留“待核验”，不得编造。
4. 法规修订时优先更新法规主表的状态和替代链，再处理受影响条款和关联隐患。
5. 企业报告等私有来源只作为整理依据，不直接放进公开仓库。
